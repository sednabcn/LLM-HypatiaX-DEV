One-click reproducibility — full design
The architecture is the same regardless of the API key / output choice. Here's the complete picture, then the two decision branches.

What a reviewer does
    1. Click a "Launch Stack" badge in your README or paper supplementary 
    2. Land on the AWS CloudFormation console (they need a free AWS account — that's the only prerequisite) 
    3. Fill in one or two fields (region stays default, optionally paste an API key) 
    4. Click Create Stack 
    5. Wait ~4–6 hours 
    6. Find a URL in the Outputs tab — click it to get results 
That's it. No CLI, no SSH, no Docker, no Julia installation.

Architecture overview
Reviewer clicks URL
       │
       ▼
CloudFormation Stack
  ├── IAM Role          (EC2 + S3 + SSM, least-privilege)
  ├── S3 Bucket         (results + static website)
  ├── SSM Parameter     (API key, SecureString)
  ├── EC2 Spot Instance (r6i.xlarge, 32 GB, self-terminating)
  │     └── user-data bootstrap:
  │           clone repo → install deps → run pipeline
  │           → upload results → generate HTML report
  │           → self-terminate
  └── CloudFormation Output → results URL (pre-signed or public)
Everything is created fresh per reviewer run and destroyed when done. No shared state, no cleanup burden on the reviewer.

## Reproducing HypatiaX Results

Click the button below. You need a free AWS account — no other software required.

[![Launch Stack](https://s3.amazonaws.com/cloudformation-examples/cloudformation-launch-stack.png)](https://console.aws.amazon.com/cloudformation/home#/stacks/create/review?templateURL=https://hypatiax-public.s3.amazonaws.com/hypatiax-reproducibility.yaml&stackName=hypatiax-repro)

### What happens
1. AWS provisions an `r6i.xlarge` instance (32 GB RAM, 4 vCPU) in your account
2. The instance clones this repository, runs the full pipeline (~4–6 hours), uploads results to S3, then **terminates itself** — you are not charged after it finishes
3. The **Results** link appears in the CloudFormation Outputs tab when done

### Parameters you may want to change
| Parameter | Default | Notes |
|-----------|---------|-------|
| `AnthropicApiKey` | *(empty)* | Paste your key for LLM steps; leave blank to run without |
| `PysrTimeout` | 1100 | Reduce to 500 for a faster (~2h) lower-fidelity run |
| `RepoBranch` | main | Pin to a specific commit SHA for exact reproducibility |

### Estimated cost
~$5–8 USD total (Spot instance + S3). The S3 bucket auto-deletes after 30 days.

### Troubleshooting
- **Stack stays in CREATE_IN_PROGRESS for >10 min:** the instance is provisioning normally; the pipeline runs inside the instance and takes 4–6 hours
- **Spot interruption:** re-launch the stack with the same parameters; the pipeline resumes from checkpoint automatically
- **No results URL after 8h:** open the EC2 console, find the instance named `hypatiax-runner-hypatiax-repro`, go to Actions → Monitor → Get system log

Smart concern — review cycles are unpredictable and keys expire or get rotated. Here's how to handle both answers properly.

API key problem — solved with a budget-capped dedicated key + dead-man's switch
Don't use your main key. Create a dedicated reproducibility key with three layers of protection:
Layer 1 — Anthropic spending limit In your Anthropic console, create a new API key named hypatiax-repro-reviewers. Set a monthly spending limit of $50 (enough for ~8–10 full reviewer runs at ~$4–5 of LLM calls each). When the budget is exhausted, the key stops working but your main account is unaffected.
Layer 2 — AWS Secrets Manager rotation Store the key in AWS Secrets Manager rather than SSM Parameter Store. This lets you update the key value at any time without touching the CloudFormation template — reviewers always pull the current value at launch time.
bash
aws secretsmanager create-secret \
  --name hypatiax/repro/anthropic-key \
  --description "Dedicated reviewer reproducibility key — budget capped at $50/mo" \
  --secret-string "sk-ant-YOUR-DEDICATED-KEY" \
  --region us-east-1
When your key rotates or you get a new one, just update the secret — no template change needed:
bash
aws secretsmanager update-secret \
  --secret-id hypatiax/repro/anthropic-key \
  --secret-string "sk-ant-YOUR-NEW-KEY"
Layer 3 — Graceful degradation in the bootstrap If the key is missing, expired, or over-budget, the pipeline continues without LLM steps and the results page clearly marks which steps were skipped vs failed. Reviewers still get all the symbolic regression results; only the LLM-augmented comparison steps are affected.

Architecture 3 — Hybrid: self-hosted GitHub Actions runner on EC2
How it works: An EC2 instance registers itself as a GitHub Actions runner. Your CI YAML needs zero changes — just change runs-on: ubuntu-latest to runs-on: self-hosted for the Julia-heavy jobs. The instance stays running between jobs (or auto-scales with a Lambda).
# On the EC2 instance (r6i.xlarge, 32 GB):
mkdir actions-runner && cd actions-runner
curl -O -L https://github.com/actions/runner/releases/download/v2.317.0/actions-runner-linux-x64-2.317.0.tar.gz
tar xzf actions-runner-linux-x64-2.317.0.tar.gz

# Register (get token from GitHub → Settings → Actions → Runners → New runner)
./config.sh \
  --url https://github.com/YOUR_ORG/LLM-HypatiaX-PAPERS-Public \
  --token YOUR_REGISTRATION_TOKEN \
  --labels hypatiax-large \
  --name hypatiax-ec2

# Run as a service
sudo ./svc.sh install && sudo ./svc.sh start

Then in ci.yml, for the heavy jobs only:

exp2-matrix:
    runs-on: [self-hosted, hypatiax-large]   # ← only this line changes
Pros: simplest migration — existing CI YAML almost unchanged, full 32 GB RAM, no CodeBuild setup. Cons: you pay for the instance even when idle unless you add auto-start/stop via Lambda + GitHub webhooks.

One-click reproducibility — full design
The architecture is the same regardless of the API key / output choice. Here's the complete picture, then the two decision branches.

What a reviewer does
    1. Click a "Launch Stack" badge in your README or paper supplementary 
    2. Land on the AWS CloudFormation console (they need a free AWS account — that's the only prerequisite) 
    3. Fill in one or two fields (region stays default, optionally paste an API key) 
    4. Click Create Stack 
    5. Wait ~4–6 hours 
    6. Find a URL in the Outputs tab — click it to get results 
That's it. No CLI, no SSH, no Docker, no Julia installation.

Everything is created fresh per reviewer run and destroyed when done. No shared state, no cleanup burden on the reviewer.
