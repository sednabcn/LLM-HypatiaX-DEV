Orchestrated sequential execution flow for pipeline scripts

Here's the intended launch order for the four scripts:

1. pipeline_trace.py — Pre-flight structural check (run first, instant)

This is a dry-run that validates the pipeline's configuration without executing anything. It checks that step IDs are consistent, env vars are properly set, result globs are declared, and script paths resolve. Run this before touching real data:
bash

python3 pipeline_trace.py --check-scripts --show-map

2. run_all_checkpoint.py — Main pipeline orchestrator

This is the engine that runs everything in order across four phases: Setup → Core experiments → Supplementary benchmarks → Audit & verification → Outputs. It internally calls provenance_audit.py (as the provenance step) and run_notebook_as_py.py (as the audit-NB-01 through audit-NB-05 steps). Set your API key first:
bash

export ANTHROPIC_API_KEY="sk-ant-..."
python3 run_all_checkpoint.py                  # full run
python3 run_all_checkpoint.py --skip-slow      # faster, skips Feynman/noise/instability
python3 run_all_checkpoint.py --resume         # pick up from a failed checkpoint

3. run_notebook_as_py.py — Notebook runner (called by run_all, or standalone)

Normally invoked automatically by run_all_checkpoint.py during Phase 4-B. You'd only launch it directly if you want to run or debug the main experiment notebook independently:
bash

python3 run_notebook_as_py.py          # fast smoke-test mode
FAST=0 python3 run_notebook_as_py.py   # full paper-quality run

4. provenance_audit.py — Final standalone audit

Also invoked by run_all_checkpoint.py as the provenance step, but useful to run again independently after the pipeline finishes to get a clean reproducibility verdict:
bash

python3 provenance_audit.py            # human-readable report
python3 provenance_audit.py --json     # machine-readable for CI

In short: trace → run_all → (notebook + provenance automatically) → optionally re-audit standalone.
