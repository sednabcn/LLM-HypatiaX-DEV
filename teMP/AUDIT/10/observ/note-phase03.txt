Good catch to dig into run_all.sh — it answers this precisely, and it's a protocol mismatch, not just a date mismatch. There are two different experiment steps in this pipeline that could plausibly have generated "the Feynman 30-equation run," and they use completely different domain taxonomies:
The two candidate experiments
exp2_feynman (STEP 5) — this is the one that matches Table 4:
FEYNMAN_DOMAINS="feynman_biology feynman_chemistry feynman_electrochemistry
  feynman_electromagnetism feynman_electrostatics feynman_magnetism
  feynman_mechanics feynman_optics feynman_probability feynman_quantum
  feynman_thermodynamics"
That's 11 domains, using BenchmarkProtocol (the standard Feynman-benchmark domain taxonomy) — including Electrochemistry and Probability, which is exactly what showed up in the paper's tab:hardcoded table. This matches the paper's own line "30 physics equations from 11 scientific domains" word for word.
exp2 / hybrid_all_domains (STEPs 4 & 6) — this is what the August shard recompute actually used:
HYBRID_ALL_DOMAINS_EXPECTED="biology,chemistry,economics,electromagnetism,
  fluid_dynamics,mathematics,mechanics,optics,quantum,thermodynamics"
That's 10 domains, using ExperimentProtocolAll (a custom domain set that includes non-Feynman categories like Economics and Fluid Dynamics) — exactly the 10-domain list Phase03_Report.md cited for the shard files.
The smoking gun is already documented in the script itself
run_all.sh has a whole comment block (FIX-EXP2-PROTOCOL, around line 2404) describing a previous, already-diagnosed instance of this exact confusion:
"...it silently ran BenchmarkProtocol's Feynman+SRBench domains (21 raw, unmapped domain keys: feynman_biology, feynman_chemistry, ..., agriculture, energy, ..., synthetic) instead of ExperimentProtocolAll's canonical 10-domain set..."
So this isn't a hypothetical — the codebase has a known history of these two protocol classes getting swapped by mistake.
Answer
Table 4 is sourced from exp2_feynman (11-domain BenchmarkProtocol), matching its March 2026 reproduction command and its own hardcoded-equation table (Electrochemistry, Probability).
The shard recompute in Phase03_Report.md used files from exp2/hybrid_all_domains (10-domain ExperimentProtocolAll) — a structurally different experiment with a different, non-overlapping domain set (adds Economics/Fluid Dynamics/Mathematics, drops Electrochemistry/Probability/Electrostatics/Magnetism).
So the SEL/HDS mismatch isn't just "two runs five months apart" — it's two different experiment definitions being compared as if they were the same benchmark. That's a stronger, more specific finding than my earlier timestamp-only answer, and it's the more actionable one for audit_nb04: it should flag any place the paper or downstream tooling treats exp2_feynman output and exp2/hybrid_all_domains output as interchangeable "the Feynman 30" data.
