Diagnosed orphaned subprocess bug and traced cascading timeout failures
I traced the actual timeout paths end-to-end. Found two real bugs — one of which is very likely the direct cause of the 27,574s Arrhenius hang.
Bug 1 (root cause candidate): orphaned Julia process — proc.kill() doesn't reach it
In _run_pysr_in_subprocess (line 2956):
python
proc = subprocess.Popen(
    [sys.executable, "-c", _SUBPROCESS_WORKER],
    stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
    env=env,
)
...
except subprocess.TimeoutExpired:
    proc.kill()
This spawns the worker with no process-group isolation (no start_new_session=True, no preexec_fn=os.setsid). proc.kill() sends SIGKILL only to that one direct child — the wrapper python -c ... process. If that worker in turn launches Julia as its own OS subprocess (rather than loading libjulia in-process), killing the wrapper does not kill Julia. Julia becomes an orphan and keeps running, with no timeout of its own, until someone notices and kills it manually — which matches the doc's own wording: "hung for 27574s before the Julia process was killed" (not "before the subprocess timed out"). The harness's own bookkeeping (_run_pysr_in_subprocess returning a timeout-failure dict on schedule) would look completely normal here — that's why this could hide for a whole run instead of throwing an obvious error.
Fix: isolate the child in its own process group and kill the whole group (or all descendants) on timeout:
python
proc = subprocess.Popen(
    [...],
    stdin=..., stdout=..., stderr=...,
    env=env,
    start_new_session=True,   # new process group
)
...
except subprocess.TimeoutExpired:
    import signal, os as _os
    try:
        _os.killpg(_os.getpgid(proc.pid), signal.SIGKILL)
    except ProcessLookupError:
        pass
    proc.wait()
(psutil is already imported elsewhere in the file — psutil.Process(proc.pid).children(recursive=True) is a good alternative if a process group isn't reliable in the target environment.)
Bug 2 (dead safety net): _kill_thread is called but never defined
python
import ctypes          # for _kill_thread (hard timeout enforcement)   # line 63
...
_killed = _kill_thread(_worker_thread.ident)                            # line 3529
_kill_thread is referenced twice (comment + call) and imported-for (ctypes) but there is no def _kill_thread anywhere in the file, and it isn't imported from elsewhere. The call sits inside:
python
try:
    ...
    _killed = _kill_thread(_worker_thread.ident)
except Exception:
    pass  # ctypes injection is best-effort; never crash the suite
So every invocation raises NameError, which the blanket except Exception: pass silently swallows. The comments describe intended behavior ("inject SystemExit into the background thread") that has never actually run — this is the "last resort" kill that was supposed to catch exactly the runaway-thread case, and it's a no-op.
Fix: either implement _kill_thread (the standard PyThreadState_SetAsyncExc pattern) or, better, delete this dead code path and rely on Bug 1's fix — since the real problem is the orphaned OS process, not the Python thread (killing the thread wouldn't touch the Julia process either; the thread is just blocked on communicate(), it isn't doing the hanging).
