That instability you're describing is already a documented bug in your own codebase, not just a theoretical risk — worth grounding on it rather than solving from scratch.
What's already there: generate_tables.py has a load_best(subdir, glob_pat) helper that globs a directory, sorts candidates by os.path.getmtime (newest wins), and reads the first hit. There's a per-experiment table (subdir + glob pattern) documented in a comment at the top of the file, one row per experiment, since each experiment writes to a different path with a different naming convention.
Where it broke: the comment at line 222 explains a real incident — sample_complexity_n1000_checkpoint.json (an in-progress shard) matched the same glob as the final consolidated sample_complexity_<timestamp>.json, and since the checkpoint's mtime happened to be newer, load_best() silently loaded the checkpoint instead of the real result, in every CI run, producing empty tables with no error. Timestamp/mtime-based "latest wins" is exactly the kind of solution that looks portable but quietly picks the wrong file.
So the actual fix isn't "one generic loader," it's three separate disciplines, all of which your code already gestures at but only applies inconsistently:
    1. Exclude before sorting, not after. _EXCLUDE_SUBSTRINGS = ("checkpoint", "_sig", "MISSING") has to run before mtime sort, every time, in every script that touches that glob — not just in the one place someone remembered to add it.
    2. One registry, not three. The (experiment → subdir, glob pattern) table exists as a comment in generate_tables.py, but generate_figures.py and run_analysis.py each reason about paths independently (that's how the exp1_ablation vs ablation/exp1_ablation subdir mismatch bug happened, per the same comment block). Making that table a real importable Python dict that all three files import is the portable part — not the mtime trick.
    3. Detect shape from content, not filename. run_analysis.py's _load_records_from_json already does this right: it sniffs Shape P/S/N/A by which keys are present in the loaded JSON, rather than assuming structure from which experiment it is. That's the pattern to extend, since "different structure per experiment" is a losing battle to hardcode per-experiment but a solvable one to detect per-file.
