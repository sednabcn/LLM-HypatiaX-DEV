Two scripts now do this end-to-end instead of me hand-transcribing:
extract_table_rows.py — statically parses the three .tex files for every \label{tab:...} + its caption, then parses generate_tables.py function-by-function to find each table's generated filename and status. It anchors label→function matches on the two authoritative signals (a literal \label{tab:...} inside the LaTeX the function builds, or a tab:... mention inside a skip_table() reason) rather than any stray mention of a label in a comment — my first pass got this wrong and mis-attributed several rows before I tightened it. Writes table_data.py.
build_pdf.py — reads table_data.py and renders the landscape PDF with reportlab, color-coding the status column.
Run both in sequence and the PDF is fully reproducible:
bash
python3 extract_table_rows.py   # re-scan .tex + generate_tables.py → table_data.py
python3 build_pdf.py            # table_data.py → table_of_tables.pdf
Worth knowing about this automation's limits:
    • It correctly flags 3 labels as REVIEW NEEDED (baseline, projected, cost_accuracy_tradeoff) rather than guessing — those genuinely have no generator function, matching what we found by hand.
    • The "Experiment/source" column is extracted straight from skip_table()/docstring text, so a few entries show raw f-string syntax (e.g. f'no parsable results found (src={src})') instead of prose — cosmetic, but real if you want it polished.
    • Status classification is keyword-based (looks for words like "withdrawn", "unverified", "path guessed" in each function's own docstring/comments, not its LaTeX content) — reasonably reliable here given how consistently this codebase self-documents, but wire it into CI with a diff-review step rather than trusting it blindly on a codebase with looser commenting conventions.
If someone adds or edits a gen_* function later, re-running both scripts picks it up automatically — no more hand cross-referencing.
