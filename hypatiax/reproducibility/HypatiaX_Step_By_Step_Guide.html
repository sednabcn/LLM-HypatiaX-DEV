01
Prerequisites
Set up the Python environment & API key
Before anything else, install the right Python version and all dependencies.
a
Create a virtual environment with Python 3.12
All experiments require exactly Python 3.12. Using a venv keeps dependencies isolated.
bash
python3.12 -m venv .venv
source .venv/bin/activate   # Linux / macOS
# On Windows: .venv\Scripts\activate
b
Install PyTorch — pick your platform
PyTorch must be installed before requirements.txt so the correct CUDA/CPU variant is selected. Choose the tab that matches your machine.
bash — CPU-only (Linux / macOS / Windows)
pip install torch torchvision torchaudio \
    --index-url https://download.pytorch.org/whl/cpu
⚠
CPU-only is sufficient to reproduce all results — the neural baseline trains in minutes on CPU. Only switch to CUDA if you want faster iteration on the full K=30 LLM sweep.
bash — NVIDIA GPU · CUDA 12.1 (most common)
pip install torch torchvision torchaudio \
    --index-url https://download.pytorch.org/whl/cu121
For other CUDA versions replace cu121: use cu118 for CUDA 11.8 or cu124 for CUDA 12.4. Verify your version with nvidia-smi.
ℹ
After install, confirm GPU is visible: python -c "import torch; print(torch.cuda.is_available())" should print True.
bash — Apple Silicon (M1 / M2 / M3 / M4)
pip install torch torchvision torchaudio
The standard pip wheel includes MPS support on macOS ≥ 12.3 with Apple Silicon. No special index URL needed.
ℹ
Verify MPS is available: python -c "import torch; print(torch.backends.mps.is_available())" should print True.
✓
PyTorch is pre-installed on Kaggle. Skip this step entirely — the kernel image already ships the correct GPU-enabled version. Just run pip install -r requirements.txt and torch will not be reinstalled.
bash — Kaggle notebook cell
# Verify what's already there:
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
✓
PyTorch is pre-installed on Colab. Skip this step — Colab's runtime image bundles the right CUDA-enabled torch. Just run pip install -r requirements.txt for the remaining packages.
python — Colab cell
import torch
print(torch.__version__, torch.cuda.is_available())
⚠
If Colab's torch version conflicts with a pinned version in requirements.txt, comment out the torch line in that file and let Colab's pre-installed version take precedence.
Then install the remaining dependencies
bash
pip install -r requirements.txt

c
Set your Anthropic API key
The LLM component calls Claude via the Anthropic API. You must set this before running any experiment. The included secrets.py handles Kaggle and Colab automatically — for local runs, export it in your shell or use a .env file.
⚠
Verify secrets.py is present. Check that secrets.py exists at the repro repo root before running. It is not a generated file — it must be committed to the repo. If it is missing, the Kaggle/Colab auto-loading will silently fail and all LLM calls will error.
bash — option 1: shell export
export ANTHROPIC_API_KEY="sk-ant-..."
Add this line to your ~/.bashrc or ~/.zshrc to avoid re-exporting on every session.
bash — option 2: .env file at repo root (recommended for local dev)
# Create a .env file at the repo root:
ANTHROPIC_API_KEY=sk-ant-...
# secrets.py will load it automatically via python-dotenv.
# Make sure .env is in .gitignore — never commit this file.
Go to Kaggle → Your profile → Settings → Secrets and add a secret named ANTHROPIC_API_KEY. Then secrets.py loads it automatically at startup — no manual export needed.
python — loaded automatically by secrets.py
# secrets.py calls UserSecretsClient().get_secret("ANTHROPIC_API_KEY")
# and sets os.environ["ANTHROPIC_API_KEY"] — nothing else required.
Go to Colab → left sidebar → 🔑 Secrets and add a secret named ANTHROPIC_API_KEY. Then secrets.py loads it automatically via userdata.get().
python — loaded automatically by secrets.py
# secrets.py calls userdata.get("ANTHROPIC_API_KEY")
# and sets os.environ["ANTHROPIC_API_KEY"] — nothing else required.
⚠
LLM results are stochastic

Claude uses temperature sampling — results will vary between runs. The neural-network baseline IS exactly reproducible (fixed seed 42). See §1.4 of the guide for the full reproducibility matrix.

d
Hardware note
Any machine capable of multi-process PySR execution will reproduce the qualitative findings. The paper's primary reported figures (9/30 Feynman) were obtained on a Kaggle 4-vCPU instance. Exact R² values may differ slightly across hardware due to floating-point variation in PySR's evolutionary search.
02
Configuration
Edit config/repro.yaml
All paths, seeds, and LLM settings live in one file. Edit this before running anything.
a
Open the config file and fill in the required fields
Do not edit paths.root directly — set the HYPATIAX_ROOT environment variable in your shell instead. All other paths are derived from it.
config/repro.yaml
# ── Paths ─────────────────────────────────────
# Set HYPATIAX_ROOT in your shell first:
#   export HYPATIAX_ROOT=/absolute/path/to/.../hypatiax
paths:
  root:    "${HYPATIAX_ROOT}"   # ← set env var, not this file
  results: "hypatiax/data/results"

# ── Seeds ─────────────────────────────────────
seeds:
  default:            42   # fixed for all NN runs — do not change
  pysr_seed:          42
  validation:         [123]  # seed=123 Nguyen-12 rerun (§10.8)
  portfolio_variance: [42, 99, 123, 777, 2024]  # 5-seed sweep for §10.5 Tab 4

# ── LLM ───────────────────────────────────────
llm_model:   "claude-sonnet-4-6"  # Anthropic Claude
llm_retries: 3
llm_k_runs:  30  # set to 1 for a fast check

# ── Benchmark ─────────────────────────────────
n_tasks_defi:        74
n_tasks_instability: 70   # subset used in §10.9 (FIX-T1)
pca_train_frac:      0.40   # DeFi 40/60 PCA split
nn_time_limit:       120    # wall-clock seconds per NN case
ℹ
Quick-check tip

Set llm_k_runs: 1 for a fast single-pass sanity check. Use llm_k_runs: 30 only when you need the full instability analysis from §10.9.

⚠
Provisional MW values in core15.expected

The mw_p and mw_u values in repro.yaml were computed from a populations=2 run, not populations=30. They are marked PROVISIONAL in the file. Do not use them as ground truth until the correct rerun (action guide item 2) is complete.

07
Known caveats & errata
Things that will trip you up
Read these before cross-referencing numbers with the paper.
!
Missing file: hypatiax_defi_benchmark_v3c.py not in public repo
The primary DeFi 74-task benchmark script referenced in repro.yaml as benchmarks.defi.script is absent from the public hypatiax/experiments/benchmarks/ directory. All six other benchmark scripts are present. Without this file the 89.2% accuracy result (Tab 1, §10.2) cannot be reproduced from the published code. Contact the authors or check whether the file was renamed before attempting to run the DeFi benchmark.
✗
Do not attempt to substitute another benchmark script — the DeFi task definitions, checkpoint keys, and stratum splits are specific to this runner. Running a wrong script will silently produce incorrect results.
!
Missing engine: hybrid_system_v50.py not in public repo
The canonical engine hybrid_system_v50_2 (specified in repro.yaml and the action guide) lives at hypatiax/tools/symbolic/hybrid_system_v50.py. The public tree contains only hybrid_system_v40.py. Any benchmark script that imports hybrid_system_v50_2 will fail at import. Note that repro.yaml carries the comment # NEVER use: hybrid_system_v40 — this warning is currently misleading since v40 is the only published file.
✗
Do not run benchmarks against hybrid_system_v40 and compare results to the paper — v40 is the stale engine that FIX-C2 replaced. Results will differ.
!
Corrected runtime claim (§10.4)
An earlier draft claimed a "73 % runtime reduction." The verified figure is a 1.73× speedup, applying only to the 68 LLM-routed cases (out of 74). The aggregate mean time for HypatiaX (6.8 s) is actually higher than the neural baseline (3.0 s) due to fallback costs.
✗
Do not compare "73%" from any draft version to the current table. Use only 1.73× from config/repro.yaml (see benchmarks.core15.expected — marked PROVISIONAL until the populations=30 rerun is complete).
!
Four data-generation bugs fixed in v3.0 (Supp A)
Before the final benchmark, four bugs were corrected. Results from any version prior to v3.0 should not be compared to the current paper figures.
FixDescription
Fix 0Reserve Ratio / Spot Price used identical linspace ranges (zero-variance target). Fixed to independent log-uniform sampling with seed=7.
Fix 0bImpermanent Loss Breakeven misclassified as tractable. Now flagged as intractable and excluded from the 74-case denominator.
Fix 5Unified formula evaluator eliminates divergent evaluation paths causing phantom R²=1.000 artefacts.
Fix 5b
!
In-sample routing gains (Supp A §1, Remark 3.2)
The DeFi equations used to validate routing fixes overlap with the Core-15 and DeFi-74 benchmark. Post-fix figures in Supp A should be read as in-sample routing improvement, not held-out generalisation.
!
Two different Feynman numbers — do not compare them
Two Feynman results appear in the paper and measure completely different things:
ResultProtocolSection
9/30 (30.0 %)Random 80/20 split, extrap_mult=2.0 (not comparable to DeFi)Main paper §10.7
EHD 96.7 %Noiseless protocol, no extrapolation shiftSupp B
!
Hardcoded PureLLM results (Supp B §3.3)
In the six-method noiseless Feynman comparison, 11 of the 30 PureLLM passes are flagged is_hardcoded=True. These are disclosed in Table B3 of Supp B and do not affect the HypatiaX vs. baseline comparisons.
