Here's what was built and the key design decisions behind each deliverable:

1 · run_all.py — Checkpoint/Resume pipeline
New mechanics:
    • CHECKPOINT = logs/pipeline_checkpoint.json — written atomically after every step via .tmp → .replace(). Contains {step_id: "pass"|"fail"}. 
    • --resume — skips every step already marked pass in the checkpoint. Steps that failed or never ran are re-run. 
    • --resume --from exp2 — steps before exp2 that passed are still skipped; exp2 and everything after runs unconditionally. 
    • --clear-checkpoint — deletes the file and exits (for fresh starts). 
    • RESULTS_DIR = hypatiax/data/results/ — propagated to all child processes as $RESULTS_DIR. ensure_output_dirs() creates the full subdirectory tree on first run. 
    • archive_step_results(step) — after each passing step, snapshots its primary outputs (via result_glob) into logs/<step_id>_results/ for provenance. 
    • figures/ and tables/ steps now pass --outdir hypatiax/data/results/figures and --outdir hypatiax/data/results/tables explicitly. 
    • inventory_results() in the summary prints counts of JSON+CSV, PDF figures, and TeX tables actually on disk. 
    • Checkpoint is cleared automatically at the end of a fully passing run; preserved on any failure. 

2 · ci.yml — GitHub Actions (.github/workflows/ci.yml)
Five jobs, scoped to cost and trigger:
Job	Trigger	What it does
lint	every push/PR	ruff, stale-v40 check, exposed-key scan, validate — no API key, fast
smoke-test	push/PR	Phase 0 + exp3 only — catches import breakage quickly
full-pipeline	push to main	All non-slow steps + figures + tables + verify
slow-pipeline	manual dispatch	Full pipeline with LLM_K_RUNS=30
verify	PR	verify-only against cached results from main
Checkpoint and result files are cached between runs using actions/cache with branch-scoped keys, so a preempted run resumes automatically on retry.
